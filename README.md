# Անձնական և թիմային ռեժիմներ

Նախագիծ ստեղծելիս setup-ում բացեք «Նախագծի անվանումներ և գույներ» բաժինը և ընտրեք պորտերի նշանակությունների ու վիճակների անուններն ու գույները։ Ընտրությունը պատկանում է տվյալ նախագծին, պահպանվում է բազայում և JSON պատճենում, կիրառվում է պորտերի, որոնման ու հաշվետվությունների մեջ։ Դատարկ անունը պահպանում է HY/EN/RU սկզբնական թարգմանությունը։ Հետագայում նույն ձևը բացվում է «Կարգավորումներ → Ընկերություն և շենք → Նախագծի անվանումներ և գույներ» կոճակով։ Գույների նախկին մեծ քարտը հեռացված է։ Սարք ստեղծելիս կարելի է ընտրել նոր պորտերի սկզբնական վիճակն ու նշանակությունը, ինչպես նաև սարքի գույնը։

Վերևի ☾ / ☀ կոճակը փոխում է գիշերային և ցերեկային ռեժիմները՝ նաև մուտքի ու սկզբնական ընտրության էջերում։ Առաջին բացման ժամանակ ընտրվում է սարքի գունային ռեժիմը, իսկ ձեռքով ընտրությունը պահպանվում է տվյալ բրաուզերում։ Փոխարկումը չի վերաբեռնում էջը և չի փոխում խմբագրվող տվյալները։ Տպման տարբերակը մնում է բաց գույներով։

2026-09-09 թարմացում. սկզբնական էջն ունի **Այս սարքում / Վերականգնել / Հաշիվ և անձնական cloud** տարբերակները։ Վերականգնման աղբյուրներն են JSON-ը, անձնական PIN-ը, թիմային PIN-ը և Google Drive-ը։ Տեղական ռեժիմն ընտրելուց հետո դատարկ բազան բացում է շենքի ստեղծման ձևը։

Անձնական cloud-ի համար կիրառեք `npm run cloud:migrate` (միգրացիա 004)։ Գրանցումը կատարվում է Supabase email/password-ով. հաստատման նամակից հետո առաջին հաջող մուտքը ստեղծում է անձնական տարածք ու ցուցադրում 12-նիշ PIN։ Ներբեռնեք PIN-ը. սերվերը պահում է միայն hash-ը։ Էլ․ փոստ + անձնական PIN-ը տալիս է սեփական ֆայլերի դիտման/ներբեռնման իրավունք, գաղտնաբառով մուտքը՝ խմբագրման։ Կարգավորումներում PIN-ի փոխարինումն անմիջապես անվավեր է դարձնում հին PIN-ը և դրա նիստերը։ Թիմային ցուցակներն ու արտահանումները անձնական տվյալներ չեն պարունակում։

Google Drive-ի պահպանման/վերականգնման կոդը պատրաստ է, բայց կապն ակտիվացնելու համար պահանջվում է `GOOGLE_DRIVE_CLIENT_ID`։ Google Cloud-ում միացրեք Drive API-ն և OAuth Web Client-ի JavaScript origins-ում ավելացրեք `https://patch.ditaknet.com`։ Օգտատերը հաստատում է `drive.appdata` թույլտվությունը. տվյալները անմիջապես պահվում են նրա Drive-ում, token-ը մնում է բրաուզերի հիշողությունում։ «Պահել Drive-ում»-ը ստեղծում է ընտրված ընկերության նոր պատճեն։ Ավտոմատ Drive համաժամացում այս տարբերակում չկա։ Supabase-ում ավելացրեք նաև կայքի URL-ը թույլատրված վերադարձի հասցեներում։


Վերևի **HY / EN / RU** ընտրիչով փոխեք միջերեսի լեզուն։ Ընտրությունը պահպանվում է այս բրաուզերում։ Ձևերը, հաղորդագրությունները և Excel/PDF հաշվետվությունները օգտագործում են ընտրված լեզուն, իսկ ընկերությունների անուններն ու մուտքագրված տվյալները չեն թարգմանվում։ PDF-ի DejaVu Sans տառատեսակն աջակցում է երեք լեզուներին․ լիցենզիան՝ `assets/fonts/LICENSE_DEJAVU`։

«Իմ փաչ»-ը ամեն բացման ժամանակ առաջարկում է երեք ընտրություն՝ սկսել անձնական նախագիծ, վերականգնել JSON պատճենը կամ միանալ թիմային տարածքին։ Հին պահպանված ռեժիմը կամ բազայի առկայությունը չեն շրջանցում ընտրության էջը։ Կարգավորումներ → «Ընտրել աշխատանքային տարածքը» կոճակով կարելի է վերադառնալ այս էջ։ Արդեն գոյություն ունեցող անձնական տվյալները պահպանվում են։ Անձնական աշխատանքը մուտք կամ PIN չի պահանջում․ տվյալները պահվում են միայն տվյալ բրաուզերի IndexedDB-ում։ Առաջին ամբողջական բեռնումից հետո անձնական տարբերակը բացվում է նաև առանց ինտերնետի։ Բրաուզերի տվյալները մաքրելը կարող է ջնջել այդ բազան․ պահեք JSON պատճեն։

Կարգավորումներ → «Միացնել cloud-ը» → թիմային PIN կամ, եթե PIN-ը միացված չէ, կարգավորված Supabase հաշվի մուտք։ Մուտքից հետո բացվում է ընդհանուր բազան, փոփոխությունները պահպանվում են ավտոմատ, մյուս աշխատակիցները տեսնում են դրանք հերթական թարմացման ժամանակ (մոտ 5 վրկ)։ Ինտերնետը պարտադիր է թիմային աշխատանքի համար։ «Անցնել անձնական ռեժիմի» կոճակը վերադարձնում է այս սարքի առանձին բազան։

Ամպային մի քանի PIN-ի համար կիրառեք `migrations/003-multiple-pins.sql`-ը (`npm run cloud:migrate`), ապա `npm run pin:cloud -- --count 3`՝ սերվերային կապի փոփոխականներով։ Կոդերը գրվում են միայն `%LOCALAPPDATA%/RackMap/MyPatch-cloud-PINs-*.txt` մասնավոր ֆայլերում։ Բազայում պահվում են աղապատ hash-երը և session secret-ը՝ RLS-ով պաշտպանված, հանրային դերերին անհասանելի աղյուսակներում։ PIN-երը չեն արտահանվում ընկերությունների պահուստային պատճեններով։ Մեկ PIN-ը անջատելու համար սերվերային բազայում նշեք `rackmap.pin_keys.enabled=false`՝ համապատասխան ID-ի համար․ դրա գործող նիստն էլ անմիջապես կդադարի աշխատել։ Մյուս PIN-երը կմնան գործող։ Յուրաքանչյուր PIN տալիս է նույն թիմային բազայի խմբագրման իրավունք, իսկ նիստը գործում է մինչև 8 ժամ։

Ռեժիմի փոփոխությունը չի ջնջում և ինքնաբերաբար չի վերբեռնում անձնական ընկերությունները։ Եթե պետք է փոխանցել մեկ ընկերություն՝ անձնական ռեժիմում ներբեռնեք JSON-ը, ապա cloud-ում նոր ընկերություն ստեղծեք և վերականգնեք JSON-ը այնտեղ։ Ընթացիկ ընկերության տվյալները կփոխարինվեն այդ JSON-ով՝ ծրագրի գործող հաստատման քայլից հետո։

Անձնական Excel-ը ստեղծվում է սարքում։ Անձնական PDF-ի կոճակը բացում է բրաուզերի տպումը՝ ընտրեք Save as PDF։ Տեղական Windows LAN տարբերակը լռելյայն շարունակում է օգտագործել իր սերվերի բազան, իսկ Կարգավորումներից կարելի է անցնել անձնական ռեժիմ։

# Ditaknet փաչ պանել

Հայերեն վեբ ծրագիր՝ մի քանի ընկերությունների հարկերի, ռաքերի, փաչ պանելների, սվիչների և մալուխների կապերի կառավարման համար։ Աշխատում է Windows համակարգչի վրա և նույն տեղական ցանցի հեռախոսներից ու համակարգիչներից։

## Ընկերություններ և նոր գործիքներ

Ձախ կողմի ընտրացանկով անցեք ընկերությունների միջև կամ սեղմեք «Նոր ընկերություն»։ Ընկերություններն ունեն առանձին հարկեր, ռաքեր, կապեր, տարբերակներ և պահպանման պատմություն։ Փոխելուց առաջ ընթացիկ աշխատանքը պահպանվում է։

Յուրաքանչյուր ընկերության JSON ֆայլը կարելի է ներբեռնել կամ վերականգնել Կարգավորումներից։ Վերականգնումը վերաբերում է ընտրված ընկերությանը։ Կա նաև բոլոր ընկերությունների ամբողջական SQLite պատճենի ներբեռնում։

Ռաքի աջ խմբագրիչը համակարգչում ֆիքսված է էկրանին, իսկ կենտրոնական հատվածն առանձին է թերթվում։ «3D կապեր» կոճակը բացում է պտտվող դիտում. ընտրեք մալուխը՝ դրա երկու ծայրերն ընդգծելու համար։ Պատկերը հաշվարկվում է գրանցված կապերից և չի ներկայացնում մալուխի իրական ֆիզիկական երթուղու չափագրությունը։

## Օգտագործել թիմով

«Կարգավորումներ → Թիմի հասանելիություն» բաժնում ցուցադրվում են համակարգչի ցանցային հասցեները։ Դրանցից համապատասխան հասցեն բացեք նույն ցանցի հեռախոսով կամ այլ համակարգչով։ Հիմնական համակարգիչը և սերվերը պետք է միացված մնան։ Հասանելիությունը կարող է պահանջել Windows Firewall-ում Node.js-ի թույլտվություն մասնավոր ցանցի համար։ Աշխատակիցների PIN-ի կարգավորումը՝ npm run pin:setup։ Ամպային մուտքը պահանջում է PIN կամ Ditaknet-ի թույլատրված հաշիվ։

## Հիմնական գործողություններ

- **Հարկեր** — ավելացնել, անվանափոխել, խմբով ավելացնել և ջնջել։ Նկուղը կարելի է նշել որպես առանձին անվանված հարկ։
- **Ռաքեր** — մի քանի ռաք յուրաքանչյուր հարկում, հարկերի միջև տեղափոխում, տեղադրության նկարագրություն, պատրաստի 6U/9U/12U/24U/42U կամ ձեռքով 1–60U չափ։
- **Սարքեր** — փաչ պանել և սվիչ, անուն, մոդել, գույն, U դիրք ու բարձրություն։ Սարքի տեղը փոխվում է խմբագրման քարտից։ U1-ը ներքևում է, սարքի բարձրությունն աճում է դեպի վեր։
- **Չափեր** — փաչ պանելներ՝ 12, 24, 48 պորտ։ Նոր սվիչ ընտրելիս առաջարկվում է 28 կամ 48 պորտ։ Հին այլ քանակով սարքերը պահպանվում են։ Կան 1U/2U ձևանմուշներ, բարձրությունը նաև ձեռքով է փոխվում։ Ձևանմուշի չափը ճշտեք իրական մոդելի հետ։
- **Պորտեր** — սեղմեք ռաքի գունավոր պորտը կամ բացեք սարքի պորտերի մեծ ցանկը։ Լրացրեք մալուխի պիտակը, նպատակակետի հարկը, սենյակը, դուռը, կողմը, նշումները և սվիչի պորտը։
- **Կապեր** — մի փաչ պորտը կապվում է մեկ սվիչի պորտի։ Նույն սվիչի պորտը կրկնակի ընտրել չի թույլատրվում։ Սվիչի կողմից հնարավոր է բացել համապատասխան փաչ պորտի քարտը։
- **Վիճակներ** — կանաչ՝ ազատ, կապույտ՝ զբաղված, կարմիր՝ անսարք։ Անսարք պորտը կարող է պահպանել իր ֆիզիկական կապը։ Կապի առկայությունն ինքնաբերաբար զբաղեցնում է սվիչի պորտը։
- **Լուսանկար** — PNG/JPEG/WebP, մինչև 12 ՄԲ մուտքային ֆայլ։ Լուսանկարը չափափոխվում է մինչև 1600 պիքսել և պահվում որպես JPEG։ Կարելի է դիտել մեծացված, փոխել կամ հեռացնել։
- **Որոնում** — սվիչ, սարք, պորտ, ռաք, մալուխ, հարկ, սենյակ, դուռ, կողմ և նշումներ։ Հարկի ֆիլտրը հաշվի է առնում և՛ ռաքի, և՛ մալուխի նպատակակետի հարկը։
- **Հաշվետվություններ** — իրական `.xlsx` և `.pdf` ֆայլեր։ Արտահանվում են ֆիլտրին համապատասխան բոլոր պորտերը՝ ներառյալ ցուցակի հաջորդ էջերը։ Excel-ում կա նաև ռաքերի ու սարքերի գույքագրման թերթ։ Փաչ և սվիչի պորտերը առանձին տողեր են, հետևաբար մեկ կապը կարող է երևալ երկու ծայրերով։

## Պահպանում և վերականգնում

Պորտերը խմբագրվում են ռաքի աջ կողմի գործիքների վահանակում՝ առանց առանձին պատուհանի։ Դաշտերի փոփոխությունը 0.6 վայրկյան անց վավերացվում է, ապա ինքնաբերաբար ուղարկվում ընդհանուր բազա։ «Պահպանել» կոճակով կարելի է պահպանել անմիջապես։ Այլ պորտ ընտրելիս ընթացիկ փոփոխությունը պահպանվում է, իսկ սխալ VLAN-ի դեպքում ընտրությունը կանգ է առնում՝ մինչև ուղղումը կամ «Չեղարկել» կոճակը։ «Պահված է» գրությունը հայտնվում է միայն սերվերի հաստատումից հետո։

«Link config»-ում ընտրեք նշանակությունը՝ տեսախցիկ, Wi-Fi, Access control, հեռախոս կամ Internet։ Գույնը երևում է կապի երկու ծայրերում։ Փոքր կետը ցույց է տալիս պորտի վիճակը, «!» նշանը՝ անսարքությունը։ VLAN-ը կարող է լինել 1–4094 ամբողջ թիվ կամ դատարկ և տեղեկատվական գրառում է. ծրագիրը սվիչի կոնֆիգուրացիա չի փոխում։ Նշանակությունն ու VLAN-ը ներառված են որոնման և Excel/PDF արտահանման մեջ։ Նախկին բազաներն ու պատճեններն աշխատում են նաև առանց այս նոր դաշտերի։

Բազան կոդից առանձին է՝ `%LOCALAPPDATA%\\RackMap\\rackmap.sqlite`։ Այս համակարգչում՝ `C:\\Users\\RoyalArm\\AppData\\Local\\RackMap\\rackmap.sqlite`։ Ընկերությունները տրամաբանորեն առանձնացված են նույն բազայում։ SQLite-ն պահում է նաև վերջին 50 փոփոխություններից առաջ եղած վիճակները։ Դրանք հասանելի են «Կարգավորումներ → Պահպանման պատմություն» բաժնում։ Ջնջումները ևս վերականգնելի են այնտեղից, քանի դեռ համապատասխան տարբերակը չի դուրս եկել վերջին 50-ից։

Բազայի կառուցվածքի փոփոխություններից առաջ, յուրաքանչյուր գործարկման ժամանակ և օրափոխությունից հետո պարբերական ստուգմամբ ստեղծվում են ստուգված SQLite պատճեններ՝ հարևան `backups` պանակում։ Հին `data/rackmap.sqlite` ֆայլից տեղափոխումը կատարվում է առանց սկզբնական ֆայլը ջնջելու։ Ավելի նոր schema-ով բազան հին ծրագիրը չի վերագրում։

Ամբողջ SQLite պատճենի վերականգնումից առաջ կանգնեցրեք սերվերը, գործող տվյալների պանակը պահեք առանձին և պատճենը տեղադրեք որպես նոր `rackmap.sqlite`՝ առանց հին WAL ֆայլերի։ Միայն մեկ ընկերության JSON պատճենը կարելի է վերականգնել ծրագրի ներսում։

«Ներբեռնել» կոճակով պահեք անկախ JSON պատճեն։ Այդ ֆայլը ներառում է լուսանկարներն ու ամբողջ շենքը և կարող է վերականգնվել նոր համակարգչում։ Պատմության պատճենները նույն բազայում են, ուստի սկավառակի կորստից պաշտպանվելու համար պահեք JSON-ը նաև այլ կրիչում։

Միաժամանակ աշխատելիս ծրագիրը ստուգում է տարբերակի համարը։ Եթե մեկ ուրիշն արդեն փոխել է տվյալները, ձեր փոփոխությունը չի վերագրում նրա աշխատանքը։ Ծրագիրը ցույց է տալիս հաղորդագրություն, պահում է տեղական վերականգնման պատճեն և առաջարկում ներբեռնել ձեր տվյալները կամ բեռնել ընդհանուր տարբերակը։ Հետո կրկնեք ձեր փոփոխությունը նոր տարբերակի վրա։ Բարդ ավտոմատ միաձուլում չի կատարվում։

Ընդհանուր տվյալների փոփոխությունը ստուգվում է 5 վայրկյանը մեկ, երբ խմբագրման պատուհան բաց չէ։ Կապի բացակայության դեպքում նոր փոփոխությունները չեն համարվում պահպանված։ Հին MVP-ի `rackmap-mvp-v1` բրաուզերային պահոցը չի ջնջվում և ինքնաբերաբար չի ներմուծվում, քանի որ այն առանձին origin-ում է և կարող է պարունակել անվավեր U դասավորություն։

Բազայում պահվում է ամբողջ շենքի վավերացված JSON վիճակը՝ մեկ տրանզակցիայով։ Տարբերակը համեմատվում է նույն տրանզակցիայի ընթացքում։ Հարցումները պարամետրավորված են, բազայի և ծրագրի ներքին ֆայլերը HTTP-ով չեն տրամադրվում։

Ծավալի ընթացիկ սահմանները՝ 200 հարկ, 100 ռաք յուրաքանչյուր հարկում, 60U ռաք, 96 սվիչի պորտ և 24 ՄԲ ընդհանուր պահպանման հարցում։ Սահմանները կիրառվում են յուրաքանչյուր ընկերության համար։ Սարքերի ավտոմատ հայտնաբերում, SNMP և սվիչների կարգավորում չի իրականացնում։

Հայերեն PDF-ի համար Windows-ում օգտագործվում է `C:/Windows/Fonts/sylfaen.ttf`։ Այլ համակարգում `RACKMAP_FONT` միջավայրի փոփոխականով նշեք հայերեն պարունակող TTF տառատեսակի բացարձակ ուղին։ `PORT` և `HOST` փոփոխականներով կարելի է փոխել պորտն ու լսելու հասցեն։

Պատճենման մեթոդ՝ [SQLite VACUUM INTO](https://www.sqlite.org/lang_vacuum.html)։

Պաշտոնական տեխնիկական տեղեկանքներ՝ [Node.js SQLite](https://nodejs.org/api/sqlite.html), [ExcelJS](https://github.com/exceljs/exceljs), [PDFKit տեքստ և տառատեսակներ](https://pdfkit.org/docs/text.html)։
